# 렌더링 파이프라인 (Rendering Pipeline)

본 문서는 `DontStarve_WinAPI` 프로젝트의 그래픽스 렌더링 흐름과 구조를 설명합니다. 이 시스템은 **GDI+**를 기반으로 하며, 성능 최적화와 올바른 깊이 표현을 위해 **더블 버퍼링(Double Buffering)** 및 **데이터 지향 설계(Data-Oriented Design)** 기반의 커맨드 패턴을 사용합니다.

---

## 1. 핵심 컴포넌트

### 1.1 GraphicsManager
- **역할**: GDI+ 초기화 및 메인 백버퍼(백버퍼 비트맵) 관리.
- **더블 버퍼링**: `m_pDoubleBufferBitmap`에 모든 그림을 그린 후, 최종적으로 `BitBlt`을 통해 실제 화면(HDC)으로 한 번에 복사하여 화면 깜빡임을 방지합니다.
- **성능 설정**: `NearestNeighbor` 보간법과 `HighSpeed` 스무딩 모드를 사용하여 픽셀 아트 스타일을 유지하고 성능을 확보합니다.

### 1.2 RenderManager
- **역할**: 렌더링 명령 수집, 정렬 및 실행.
- **레이어 시스템**: 레이어별 독립된 커맨드 큐를 운영하여 렌더링 순서를 보장합니다.
- **Z-Ordering**: 같은 레이어 내에서 `zOrder` 값을 기준으로 정렬을 수행합니다.

### 1.3 CameraManager
- **역할**: 월드 좌표와 화면 좌표 간의 변환.
- **좌표 변환**: `WorldToScreen` 함수를 통해 월드 상의 객체 위치를 카메라 시점에 맞춘 화면 좌표로 변환하여 `RenderManager`에 전달합니다.

---

## 2. 데이터 구조: DrawCommand (Data-Oriented Design)

`RenderManager`의 성능 핵심은 연속된 메모리 구조를 활용하는 **태그된 공용체(Tagged Union)** 설계에 있습니다.

### 2.1 Union과 내부 구조체 설계의 이점
- **메모리 효율성**: `SpriteData`, `TextData`, `PrimitiveData`가 메모리 공간을 공유합니다. 명령 객체는 이 중 가장 큰 구조체의 크기로 고정되므로, 다형성(Polymorphism)을 위해 포인터를 사용하는 방식보다 메모리 파편화가 적고 효율적입니다.
- **캐시 지역성 (Cache Locality)**: 모든 명령이 동일한 크기를 가지므로 `std::vector<DrawCommand>` 내부에 데이터가 빈틈없이 연속적으로 배치됩니다. 이는 CPU가 렌더링 명령을 순회할 때 **캐시 미스(Cache Miss)를 최소화**하여 처리 속도를 극대화합니다.
- **오버헤드 제거**: 가상 함수 테이블(vtable)이나 동적 할당(`new`/`delete`) 없이 단순한 값 복사만으로 명령을 생성하고 관리할 수 있습니다.

---

## 3. 정렬 및 처리 전략 (Sorting Strategy)

`RenderManager::Flush`는 두 단계의 정렬 과정을 거쳐 최종 화면을 구성합니다.

### 3.1 1차 분류: 레이어 기반 다중 큐
- `m_layerCommands[LAYER_COUNT]` 배열을 사용하여 명령 등록 시점에 레이어를 즉시 분류합니다.
- 레이어 간의 정렬(예: 타일은 항상 캐릭터 아래에 그림)을 루프 순서만으로 해결하므로 별도의 전역 정렬 비용이 발생하지 않습니다.

### 3.2 2차 정렬: 레이어 내 Z-Order 정렬
- 각 레이어 내부에서 `std::stable_sort`를 수행합니다.
- **Stable Sort의 중요성**: 동일한 `zOrder`를 가진 객체들 사이에서 등록 순서를 유지함으로써, 렌더링 결과의 일관성을 보장합니다.
- **Y-Sorting**: 월드 오브젝트 레이어에서는 객체의 Y 좌표를 `zOrder`로 사용하여 2D 환경에서 입체적인 깊이감을 구현합니다.

---

## 4. 렌더링 단계 (Rendering Steps)

1. **초기화**: `GraphicsManager`가 백버퍼를 검은색으로 Clear합니다.
2. **명령 수집**: 모든 객체가 자신의 데이터를 `DrawCommand` 형태로 적절한 레이어 큐에 추가합니다.
3. **정렬 및 실행**: `RenderManager::Flush`가 레이어 순서대로 내부 정렬 후 GDI+를 통해 백버퍼에 그립니다.
4. **화면 출력**: `BitBlt`을 통해 백버퍼의 내용을 실제 윈도우 화면으로 전송합니다.

---

## 5. 기술적 한계 및 개선 방향

### 5.1 GDI+ 및 CPU 렌더링의 한계
- **ImageAttributes 의존성**: 색상/투명도 변환을 위해 무거운 `ImageAttributes` 객체를 거쳐야 하는 API 제약이 있습니다.
- **Overdraw 부하**: 가려진 픽셀을 스킵하지 못하고 모든 레이어를 순차적으로 덧그리는 구조라 레이어가 많아질수록 CPU 부하가 증가합니다.
- **단일 스레드**: GDI+의 특성상 멀티 코어를 활용한 병렬 렌더링이 불가능합니다.

### 5.2 DirectX 전환 시 기대 효과
- **GPU 가속**: 픽셀 셰이더(HLSL)를 통해 `ImageAttributes` 없이 실시간 색상 변환 및 광원 효과를 처리할 수 있습니다.
- **배칭(Batching)**: 수천 개의 스프라이트를 단 한 번의 드로우 콜로 처리하여 정렬 및 명령 호출 오버헤드를 제거할 수 있습니다.
- **깊이 버퍼(Depth Buffer)**: CPU 수준의 정렬 연산 없이 GPU 하드웨어 레벨에서 픽셀 단위 깊이 판정을 수행할 수 있습니다.
